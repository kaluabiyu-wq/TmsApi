# Phase 2 audit and applied changes

Audit basis: the supplied TMS project ZIP and the Phase 2 requirements in the TMS advanced roadmap.

## Initial archive findings

The archive already contained the waitlist domain entity, EF configuration, DbSet, migrations, waitlist service and DTOs, SignalR notifier/hub, and a maintenance worker class. However, the V2 waitlist controller source was entirely commented out, the maintenance worker was not registered, the Angular source had no waitlist screen/service/model/route, and there were no waitlist-specific tests.

## Changes applied in this package

1. Activated the V2 waitlist controller with authenticated endpoints and staff-only course queue/offer operations.
2. Registered `WaitlistMaintenanceWorker` as a hosted service so expired offers and newly available seats are processed in the background.
3. Added the Angular waitlist model, API service, student/admin page, route, and navigation entry.
4. Added a SignalR client for `/hubs/waitlist`; students can receive offer/expiry events while the waitlist page is open. The hub now requires authentication.
5. Made normal enrollment creation use the same course-row lock as waitlist allocation. Capacity checks count pending/approved enrollments and active offers. A new direct enrollment is also prevented from jumping ahead while an active waiting queue exists.
6. Updated enrollment-handler unit tests to use the new atomic enrollment operation.
7. Added setup, endpoint, migration, and identity-limitation documentation.

## Existing database objects

The original archive already included `20261116140421_waitlist` and `20261116163050_SyncWaitlistModel`, plus the model snapshot. No additional database migration was generated by these source changes.

## Remaining work before production

- The project has no `Student.UserId` relationship and the JWT has no Student ID claim. The current waitlist API follows the existing enrollment API convention of accepting a supplied numeric Student ID. Implement account-to-student ownership checks before production use; also restrict SignalR group membership to the authenticated student's own ID.
- Add automated integration tests against PostgreSQL for joining, duplicate prevention, queue order, accept, cancel, expiry/re-offer, and concurrent seat allocation. Existing unit tests cover enrollment-handler outcomes but do not fully exercise the waitlist service.
- Apply the existing migrations to a backed-up target database and verify the schema before deploying.

## Build/test status

This environment did not have the .NET SDK installed, so `dotnet build` and `dotnet test` could not be run. Angular dependencies could not be fully installed within the available execution window; `ng build` therefore could not run either. The supplied environment also had Node 22.16.0, below Angular 22's declared Node 22.22.3 minimum. Do not treat this ZIP as a verified production build until the build and test commands in `WAITLIST-MANAGEMENT.md` pass on a supported toolchain.

No changes were pushed to GitHub and no production deployment was performed from this local ZIP.
